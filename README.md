# 우리집 가계부 (Couple Finance Dashboard)

부부가 함께 쓰는 가계부. 순수 HTML/CSS/ES Module + Supabase(Postgres + Realtime).

---

## 🚨 지금 바로 해야 할 일 (순서대로)

### 1. Supabase 에서 `supabase_setup.sql` 실행
Supabase 대시보드 → **SQL Editor** → `supabase_setup.sql` 전체 붙여넣기 → **Run**

이 스크립트가 하는 일:
- 테이블 5개 생성 (컬럼명은 앱 JSON 키에 맞춘 camelCase)
- **RLS(Row Level Security) 활성화 + 로그인 사용자 전용 정책**
- Realtime 발행 등록
- 초기 버전이 심어둔 샘플 데이터 삭제

> ⚠️ RLS 가 꺼져 있으면 `js/supabaseClient.js` 의 anon key 를 본 누구나
> 가계부 전체를 읽고 지울 수 있습니다. 이 단계를 건너뛰지 마세요.

### 2. Supabase Auth 설정
Authentication → Providers → **Email** 활성화.
테스트 편의를 위해 "Confirm email" 을 끄면 가입 즉시 로그인됩니다.

### 3. 앱에서 계정 2개 만들기
앱을 열면 로그인 화면이 뜹니다. **[처음이신가요? 계정 만들기]** 로
남편/아내 계정을 각각 한 번씩 생성하세요. 이후에는 자동 로그인됩니다.

### 4. (선택) 부부 이메일만 허용
`supabase_setup.sql` 하단 주석의 `household_only` 정책에 두 분 이메일을 넣고 실행하면,
다른 사람이 가입하더라도 데이터에 접근할 수 없습니다.

## 실행 방법

ES Module 을 쓰므로 `file://` 로 열면 동작하지 않습니다. 로컬 서버가 필요합니다.

```bash
python3 -m http.server 8000
# http://localhost:8000
```

### 데모 모드
```
http://localhost:8000/?demo=1   # 샘플 데이터로 화면 확인 (클라우드에 저장 안 됨)
http://localhost:8000/?demo=0   # 데모 해제
```
데모 모드에서는 Supabase 에 **아무것도 쓰지 않습니다.**

## 📱 홈 화면에 추가해서 앱처럼 쓰기

아이콘과 매니페스트가 들어 있어 **홈 화면에 추가하면 앱처럼 전체화면으로 열립니다.**
(Safari 주소창·탭바 없이 실행됩니다)

**아이폰** — Safari 로 접속 → 공유 버튼 → `홈 화면에 추가`
**안드로이드** — Chrome 으로 접속 → 메뉴 → `앱 설치` 또는 `홈 화면에 추가`

아이콘을 바꾸려면 `icons/icon-source.jpg` 를 원하는 **정사각형** 사진으로 바꾼 뒤
아래를 실행하면 모든 크기가 다시 만들어집니다.

```bash
python3 - <<'PY'
from PIL import Image
base = Image.open('icons/icon-source.jpg').convert('RGB')
BG = (217, 172, 142)   # maskable 여백 색
for size, name in [(180,'apple-touch-icon.png'),(192,'icon-192.png'),
                   (512,'icon-512.png'),(32,'favicon-32.png'),(16,'favicon-16.png')]:
    base.resize((size,size), Image.LANCZOS).save(f'icons/{name}', optimize=True)
for size in (192, 512):
    c = Image.new('RGB',(size,size),BG); inner = int(size*0.78)
    c.paste(base.resize((inner,inner), Image.LANCZOS), ((size-inner)//2,)*2)
    c.save(f'icons/icon-maskable-{size}.png', optimize=True)
PY
```

| 파일 | 쓰임 |
|---|---|
| `apple-touch-icon.png` (180) | 아이폰 홈 화면 |
| `icon-192 / 512.png` | 안드로이드·크롬 설치 |
| `icon-maskable-*.png` | 안드로이드가 원형·각진 모양으로 잘라 쓸 때 (안쪽 78%에 얼굴 배치) |
| `favicon-16 / 32.png` | 브라우저 탭 |

> ⚠️ 홈 화면 아이콘은 iOS 가 캐시합니다. 아이콘을 바꿨는데 그대로면
> 홈 화면에서 삭제 후 다시 추가하세요.

## 주요 기능

### 🔁 반복 거래 (고정비 자동 입력)
월세·보험료·구독료를 등록해두면 매월 자동으로 거래가 생성됩니다.
생성되는 거래 id 가 `rtx_<템플릿id>_<YYYY-MM>` 로 고정되어 있어
앱을 몇 번 열어도 **중복 생성되지 않습니다.**
설정 화면에서 추가·수정·일시중지·삭제할 수 있습니다.

반복 거래는 **금액 유형**을 고를 수 있습니다.

| 유형 | 동작 |
|---|---|
| **고정** | 매달 같은 금액으로 자동 생성 (월세, 보험료, 구독료) |
| **변동** | 자동 생성하지 않고 홈 화면에 "금액 확인 필요"로 올라옴 (관리비, 전기요금) |

변동 항목은 **지난달 실제 금액이 미리 채워진 채로** 뜨므로 숫자만 고쳐서 [확정]을 누르면 됩니다.
이번 달에 해당 없으면 [이번 달 없음]으로 넘길 수 있고, 확정한 금액이 다음 달 제안값이 됩니다.
확인하지 않은 추정 금액이 장부에 들어가 통계를 망가뜨리는 일이 없습니다.

### 💳 카드 결제일 / 청구 주기
카드 계좌에 **결산일·결제일·결제 통장**을 지정하면, 결제일이 지났을 때
`결제 통장 → 카드` 이체 거래가 자동으로 만들어집니다. 한국 카드사의 두 형태를 모두 지원합니다.

| 형태 | 설정 |
|---|---|
| 1일~말일 사용분을 **다음 달 25일** 결제 | 결산일 `말일` · 결제일 `25일` · `다음 달에 결제` |
| 전월 14일~당월 13일 사용분을 **당월 27일** 결제 | 결산일 `13일` · 결제일 `27일` · `같은 달에 결제` |

- 거래 id 가 `ctx_<카드id>_<결제월>` 로 고정되어 **중복 생성되지 않습니다.**
- 나중에 카드 사용 내역을 더 입력하면 **결제 금액이 자동으로 보정**됩니다.
- 아직 오지 않은 결제일은 미리 만들지 않습니다.
- 사용자가 직접 수정한 결제 거래는 자동 보정 대상에서 제외됩니다.
- 결제 거래는 `이체`라서 수입/지출에 이중으로 잡히지 않습니다.

계좌 화면에는 **다음 결제일**과 **지금 쌓이는 중인 청구분**이 함께 표시됩니다.
(9월 4일에 '말일 마감 / 다음 달 25일 결제' 카드라면 → 다음 결제 9/25는 8월분,
지금 긁는 돈은 10/25에 빠져나갑니다)

### 🧾 할부
거래를 입력할 때 **일시불 / 2~36개월**을 고를 수 있고, 유이자면 연 수수료율을 입력합니다.
저장하면 회차 수만큼의 거래가 한 번에 만들어집니다.

**구매 금액을 구매월에 통째로 잡지 않고 회차별로 나눕니다.**
이 앱의 월 예산·카드 결제액이 전부 "그 달에 실제로 나가는 돈" 기준이기 때문입니다.
120만원 12개월 할부를 구매월에 통째로 잡으면 그 달 예산이 터집니다.

수수료는 국내 카드사 방식(**원금 균등 + 잔액 기준 수수료**)을 따릅니다.

```
회차 원금   = 할부원금 / 개월수     (나머지 원 단위는 1회차에 반영)
회차 수수료 = 남은 원금 × 연이율/12
```

예) 120만원 · 12개월 · 연 15% → 1회차 115,000원 → 12회차 101,250원, 총 수수료 97,500원

- 각 회차는 카드 계좌에 달려 있어 **카드 청구 주기에 자동으로 포함**됩니다.
- 회차 날짜는 구매일 + N개월이며 말일이 자동 보정됩니다 (1/31 → 2/28).
- 할부금은 `고정비`로 분류되어 월말 예상 지출에서 잘못 외삽되지 않습니다.
- 대시보드에 **진행 중인 할부**(이번 달 부담액 · 남은 회차 · 잔여 총액)가 표시됩니다.
- 거래 목록에는 `🧾 할부 3/12` 뱃지가 붙고, 삭제할 때 **할부 전체 / 이 회차만**을 고를 수 있습니다.
- 할부는 신규 등록에서만 설정합니다. 기존 회차는 금액·메모만 수정할 수 있습니다.

### 📈 경과일을 반영한 분석
- **전월 비교**는 진행 중인 달을 지난달 *같은 날짜까지*와 비교합니다 (`지난달 1~4일 대비`).
- **일평균 지출**은 그 달 전체 일수가 아니라 *경과일*로 나눕니다.
- **월말 예상 지출**은 고정비를 외삽하지 않습니다.
  (1일에 낸 월세를 30번 곱하면 예상치가 터무니없이 커집니다)
  → `고정비 실제 발생액 + 변동비 일평균 × 그 달 일수`
- **예산 경보**는 초과한 뒤가 아니라 *초과할 것 같을 때* 뜹니다
  (📈 초과 예상 / 🟡 빠듯함 / 🟢 정상).

### 💪 부부의 도전 (식단 · 운동 · 공복 몸무게)
웨딩 촬영 / 결혼식까지 몸을 만들기 위한 기록 메뉴입니다. 메뉴 **부부의 도전**(폰 하단 `도전`)에서 엽니다.

- 처음 열면 **이 기기는 누가 쓰나요?** 를 한 번 고릅니다 (기기별 설정).
  각자 자기 기록만 고칠 수 있고, 상대 기록은 전부 보이지만 읽기 전용입니다.
- 날마다 **공복 몸무게 · 식단(끼니, 시간, 먹은 것) · 운동(이름, 분)** 을 적습니다. 지난 날짜도 채울 수 있습니다.
- **도전 설정**에서 촬영일 · 결혼식 · 시작일 · 각자 목표 몸무게를 정하면 D-day 와
  "목표까지 주에 몇 kg" 이 계산됩니다 (날짜·목표는 두 기기 공유).
- 몸무게는 하루 변화보다 **최근 7일 평균**을 그 전 7일과 비교해 추세로 보여줍니다.
  (공복 몸무게는 수분·염분으로 하루 0.5~1kg 씩 출렁입니다)
- 그래프는 인라인 SVG 라서 인터넷이 없어도 그려집니다.

**DB 작업은 필요 없습니다.** 새 테이블을 만들지 않고, 이미 RLS·실시간이 켜져 있는
`app_settings` 테이블에 `chl_<사람>_<날짜>` 행으로 저장합니다. (공유 설정은 `household` 한 행만 씁니다)
같은 사람·같은 날은 항상 한 행이라 중복이 생기지 않고, 백업 JSON 에도 `challengeLogs` 로 들어갑니다.

| 파일 | 역할 |
|---|---|
| `js/challenge.js` | 기록 모델, D-day · 7일 평균 · 연속 기록 계산, 데모 데이터 |
| `js/ui/challengeView.js` | 화면 |
| `css/challenge.css` | 스타일 (접두어 `ch-`) |

### 🏦 계좌 연동
계좌를 등록하면 거래 입력 시 계좌를 지정할 수 있고, 잔액이 자동 계산됩니다.
`시작 잔액 + 수입 − 지출 ± 이체` 로 산출하며, 계좌가 지정되지 않은 거래가 있으면
잔액 아래에 경고를 표시합니다. 이체는 출금/입금 계좌를 각각 지정합니다.

### 🎨 색 (Honeycomb)

앰버 · 크림 · 브라운 네 가지 색을 기준으로 `css/styles.css` 의 `:root` 토큰에 정리했습니다.
색을 바꿀 때는 개별 화면이 아니라 이 토큰만 고치면 됩니다.

| 토큰 | 값 | 쓰임 |
|---|---|---|
| `--color-primary` | `#FFC107` | 주 버튼, FAB, 활성 탭 |
| `--color-accent` | `#895129` | 헤더, 강조 텍스트 |
| `--bg-app` / `--surface` | `#FCFAEB` / `#FFFEF8` | 바탕 / 카드 |
| `--on-primary` | `#2C2014` | **앰버 위 글자** |
| `--on-dark` | `#FFFDD0` | 브라운 위 글자 |

> ⚠️ **앰버(`#FFC107`) 위에 흰 글자를 올리면 안 됩니다.** 대비가 1.63:1 이라 읽히지 않습니다.
> 짙은 글자(`--on-primary`)를 쓰면 9.73:1 이 됩니다. 앰버 배경에는 항상 `--on-primary` 를 쓰세요.

**수입/지출 색은 초록·빨강이 아니라 청록·주황입니다.**
가계부에서 가장 자주 비교되는 한 쌍인데, 초록(`#496D34`)과 빨강(`#914840`)은
적록색약에서 ΔE 0.8 — 사실상 같은 색으로 보입니다.
청록(`#007380`)/주황(`#9F422B`) 축으로 옮겨 ΔE 15.3 (적색약) · 24.2 (정상 시야)를 확보했습니다.

### 📊 차트 규칙

- **카테고리별 지출은 도넛이 아니라 순위 막대입니다.** 조각이 8개면 색만으로 구분할 수
  없습니다(적록색약 ΔE 3.0, 정상 시야로도 5.0). 막대 길이와 이름표가 이미 정체를 알려주므로
  한 가지 색만 씁니다.
- **축을 두 개 쓰는 차트를 만들지 않습니다.** 6개월 추이에서 금액과 비율을 한 그림에 넣으면
  두 척도를 비교하게 되어 반드시 오해가 생깁니다. 그래서 `금액 추이`와 `가용 잔액률 추이`
  두 개의 차트로 나눴습니다.
- 차트 라이브러리는 CDN 에서 받아옵니다. 오프라인이면 빈 칸 대신 안내 문구가 뜹니다.

설정에서 시스템 설정 따르기 / 라이트 / 다크를 고를 수 있습니다.

### ⚙️ 설정: 기기별 vs 부부 공유
설정 화면이 두 묶음으로 나뉘어 있고 각 카드에 어디에 적용되는지 뱃지로 표시됩니다.

| 구분 | 항목 | 저장 위치 |
|---|---|---|
| 📱 이 기기에만 | 테마 | localStorage |
| ☁️ 두 기기 모두 | 카드 결제 자동 생성 | Supabase `app_settings` |

공유 설정을 한쪽에서 바꾸면 배우자 기기에도 즉시 반영됩니다.

## 동기화 동작 원리

1. **로컬 우선** — 모든 입력은 먼저 localStorage 에 저장됩니다. 오프라인에서도 입력 가능.
2. **실패는 큐에 보관** — 클라우드 전송 실패 시 `couple_finance_sync_queue` 에 쌓이고,
   온라인 복귀 시 / 30초마다 / 설정 화면의 [지금 다시 전송] 으로 재시도합니다.
3. **덮어쓰지 않고 병합** — 클라우드 데이터로 로컬을 통째로 교체하지 않습니다.
   `id` 기준으로 맞추고 `updatedAt` 이 더 최신인 쪽을 채택합니다.
4. **밀린 변경이 있으면 병합을 보류** — 큐가 비어야만 클라우드 상태를 반영합니다.

헤더 뱃지로 상태를 확인할 수 있습니다:
`☁️ 실시간 연동됨` / `⏳ 저장 대기 N건` / `🔒 로컬 모드 (로그인 필요)` / `🧪 데모 모드`

## 알려진 한계 (다음 작업 후보)

- **예산은 카테고리 단위입니다.** 공동/개인별 예산은 아직 나눌 수 없습니다.
- **첨부(영수증 사진)를 붙일 수 없습니다.**
- **리볼빙을 다루지 못합니다.** 할부는 지원하지만 결제 이월(리볼빙)은 반영되지 않습니다.
- **할부 중도상환·부분취소를 다루지 못합니다.** 남은 회차를 통째로 지우고 다시 등록해야 합니다.
- **차트는 인터넷이 있어야 그려집니다.** Chart.js 를 CDN 에서 받아오기 때문입니다.
  (숫자 자체는 오프라인에서도 표·카드로 모두 보입니다)
- **카테고리 통합/이동 기능이 없습니다.** 카테고리를 지우면 과거 거래는 '미분류'가 됩니다.
